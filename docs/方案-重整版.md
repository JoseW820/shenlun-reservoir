# 新闻素材方案（重整版）

更新时间：2026-10-01
上一版：`RSSHub_新闻素材项目交接.md`

---

## 0. 这次重整到底改了什么

**一句话：从"管道视角"改成"能力视角"。**

上一版按**管道**排：抓取 → 分类 → 落地 → 归档。这个顺序把最容易的环节（抓取）放在第一位，把最值钱的环节（拆解）默认交给"人工"，却没给任何工具支撑。

重整后按**能力**排：选材 → 精读 → 沉淀 → 复用。管道降为支撑层。

对应的三个实质改动：

| # | 改动 | 原因 |
|---|---|---|
| 1 | **源要收敛，不是扩张** | 你的目标是底层逻辑 / 举一反三 / 语言表达，这三样都是**深度阅读**的产物。50 个 feed 每天几百条，训练出来的是"快速略读"，恰好是你要的反面。 |
| 2 | **输出物从"素材卡片"改成"拆解卡"** | "把素材放到 Obsidian"——如果放的是标题+链接，零价值（浏览器更好）；放全文则是电子剪报，还是没有沉淀。 |
| 3 | **新增两个闸门：分流 + 配额** | 没有闸门，收件箱必然变成垃圾场。 |

另外，上一版低估了**抓取层的维护成本**，这一点已经有实测数据（见 §5）。

## 1. 目标与验收判据

你的原话：*考公积累素材，注重底层逻辑，举一反三，提升语言表达能力，更偏向政策导向实时时政，今年大二，不着急应试，更多是方向感的培养。*

把它翻译成**可检验的判据**，否则方案没法验收：

| 能力 | 可检验的判据 |
|---|---|
| 底层逻辑 | 读完一篇政策文件，能**脱稿**说出它的骨架：背景 → 问题 → 举措 → 保障 |
| 举一反三 | 能指出同一条政策逻辑在**另外 3 个领域**的实例（例："放宽准入 → 融合业态 → 形成生态"在体育、银发、冰雪、低空经济里都出现过） |
| 语言表达 | 能**仿写**出规范的动宾短语和论述句式，而且是在没背过的情况下 |
| 方向感 | 能判断"这条政策是延续还是转向"，以及"为什么现在提" |

**这四个判据都不靠"读得多"，靠"拆得细"。** 这是整个方案的设计前提。

## 2. 素材分层（本次重整的核心）

**不是所有源对你都同等重要。** 按对上述四项目标的贡献度分四层，每层走不同策略：

| 层 | 内容 | 对你目标的价值 | 处理策略 |
|---|---|---|---|
| **A 语言与逻辑范本** | 求是网评论员/理论文选、人民日报评论、半月谈、政府工作报告、领导重要讲话 | **最高**——直接是"语言表达"和"底层逻辑"的范本 | 精读 + 仿写，进拆解队列 |
| **B 政策原文** | 国务院意见/决定/条例、发改委/工信部/财政部文件 | **高**——学结构、规范用语、问题-对策框架 | 精读，进拆解队列 |
| **C 数据与事实** | 统计局发布与解读 | 中——学"用数据支撑判断" | 只存索引 + 一句话摘要 |
| **D 动态信息** | 新闻头条、地方动态、协会通知 | 低——只用于保持"方向感" | **只进索引，不进 Obsidian** |

**关键调整**：上一版的 5 个源以 C/D 为主，A 类几乎为零。而对"语言表达"来说 A 类是养料最集中的地方。所以**下一步该补的是 A 类源（求是网理论/评论、人民日报评论、半月谈），不是先加 17 个部门网站。**

## 3. 目标流水线

```
[0] 源清单（按 A/B/C/D 分层，每层不同策略）
      │
[1] 抓取      本地 RSSHub（已验证，见 §5）        ← 需健康检查
      │
[2] 去重      台账：URL 指纹 + 对照 Zotero 已有 URL
      │
[3] 分流 ★    A/B → 精读队列；C → 索引；D → 只进索引
      │
[4] 配额 ★    每天只放行 3-5 篇进 Obsidian
      │
[5] 落地      Obsidian：拆解卡（A/B） / 轻索引（C）
      │
[6] 拆解 ★    三件套：逻辑骨架 / 可迁移表述 / 可迁移逻辑
      │
[7] 沉淀      语料库——按「逻辑功能」可检索
      │
[8] 存档      Zotero（保持手动）
      │
[9] 健康检查 ★ 横切所有：每天自检哪些 feed 返回 0 条
```

★ = 上一版没有的环节。

### 拆解卡模板（本方案最核心的产物）

```markdown
---
来源: 中国政府网
类型: 政策原文          # 政策原文 / 评论论述 / 数据解读
层级: B                 # A/B/C
日期: 2026-09-30
url: https://www.gov.cn/zhengce/content/202609/content_7082492.htm
主题簇: [消费, 体育产业]
逻辑功能: [提对策, 讲意义]   # 提对策/讲意义/析问题/定概念/举数据/谈方法
status: inbox           # inbox / reading / done
zotero_key:
---

## 一句话
用体育赛事拉动消费，从"看比赛"转向"体育消费生态"。

## 逻辑骨架
背景（消费需要新增长点）
→ 问题（赛事供给不足、消费转化率低）
→ 举措（放宽准入、丰富供给、融合业态）
→ 保障（用地、金融、人才）

## 可迁移表述
- "以…为牵引，带动…"
- "激发…活力" / "释放…潜力"
- 分条列举措时统一用动宾结构：放宽、丰富、培育、健全

## 可迁移逻辑（举一反三）
"小众需求 → 放宽准入 → 融合业态 → 形成生态"
同一条逻辑在 银发经济 / 冰雪经济 / 低空经济 中重复出现。

## 原文
<details><summary>展开全文</summary>

（RSSHub 已抓好的正文）

</details>
```

**为什么 `逻辑功能` 这个字段重要**：它是给你练语言表达用的检索轴。复习时可以问"给我所有标了『提对策』的表述"，这就是**语料库**而不是剪报堆。这是本方案对"语言表达"最直接的贡献。

## 4. 分阶段路线（按风险排序，不按功能）

上一版把"装 Docker"当第一步。重整后按**风险**排——最大的风险不是技术，是"你会不会真的读"。

| 阶段 | 做什么 | 产出 | 代码量 |
|---|---|---|---|
| **0** ✅ | 本地 RSSHub 跑通 | 已验证（§5） | 0 |
| **1** | **先不建自动化。** 手动从 RSSHub 取 3-5 篇/天，用上面的拆解卡模板精读，坚持 2 周 | 10-15 张拆解卡；**验证你会不会真的每天读** | **0** |
| **2** | 阶段 1 成立后，再做去重台账 + 分流 + 配额 + 自动落地 | 一个约 200 行的脚本 | 小 |
| **3** | 扩源：部门（发改委/工信部/农业农村部）、地方（天津）、A 类评论源 | 源清单扩到 10-15 | 配置 |
| **4** | 微信公众号 + 登录墙（单独评估，见 §6） | 可能付费，可能放弃 | 待定 |

**为什么阶段 1 不写代码**：做大二、还有 2-3 年跑道，最大的失败模式是**花三周搭基础设施、零天读书**。先证明习惯成立，再投入自动化——自动化只会放大已经成立的习惯，不会创造习惯。

## 5. 已核实的技术底座

以下全部是**实测**结果，不是推断。

### 5.1 本地 RSSHub 可用（无需 Docker）

| 项目 | 实测结果 |
|---|---|
| Node 要求 | `engines: "^22.22.2 \|\| ^24.15.0"`，本机 v24.16.0 **符合** |
| 包管理器 | `packageManager: pnpm@10.34.5`；`.npmrc` 里 `package-manager-strict=false`。用 `corepack pnpm install` 成功 |
| 安装结果 | 1037 个包，1 分 1 秒，exit code 0 |
| 启动 | `corepack pnpm dev` → `http://127.0.0.1:1200` **HTTP 200** |
| 唯一告警 | `bufferutil` / `utf-8-validate` 因缺 Visual Studio C++ 编译失败；是 `ws` 的可选依赖，回退纯 JS，不影响运行 |

### 5.2 六条路由实测（本地实例）

| 路由 | 状态 | 条目数 | 正文 |
|---|---|---|---|
| `/gov/cn/news/gwy` | ✅ 200 | 25 | 7377 字 |
| `/qstheory/toutiao` | ✅ 200 | 50 | 3319 字 |
| `/gov/stats/sj/zxfb` | ✅ 200 | 15 | 有 |
| `/gov/mof/gss` | ✅ 200 | 10 | 1134 字 |
| `/gov/zhengce/zuixin` | ❌ 503 | 0 | — |
| `/gov/mof/bond` | ❌ 503 | 0 | — |

**失效率 33%（2/6）。**

### 5.3 两条失效路由的根因（已确诊）

**不是网络问题，不是反爬——是官网改版导致路由选择器失效。**

| 路由 | 上游官网 | 根因 |
|---|---|---|
| `/gov/mof/bond` | 200，7.5 KB 正常 | 路由选 `ul.liBox li`，页面上 **`liBox` 出现 0 次**（`<ul>`/`<li>` 都在，class 名变了）→ 解析出 0 条 |
| `/gov/zhengce/zuixin` | 200，但只有 **894 字节**的 JS 空壳 | 路由选 `h4 a, div.subtitle a[title]`，页面上没有 → 解析出 0 条 |

**RSSHub 在解析到 0 条内容时返回 503。** 两条都是小补丁能修的。

### 5.4 自建严格优于公共实例

这一点推翻了之前的判断。调研发现 `/gov/stats/sj/zxfb` 和 `/gov/mof/gss` 在公共实例（`rss.owo.nz` 等）上都是 **502**，但**本地实例这两条正常**。所以自建不只是"自主可控"，而是**能多拿到 2 条 feed**。

根因也清楚：`stats.gov.cn` 有 WAF，路由需要先握手拿 `wzws_sessionid` cookie 再带 `Referer` 请求——公共实例的出口 IP 容易被 WAF 拦。

### 5.5 RSSHub 对你扩展源清单的覆盖度

仓库里有 **2014 个 namespace**。你列出的来源中，除微信和登录墙外**全部已有覆盖**：

| 你的来源 | RSSHub namespace |
|---|---|
| 中国政府网 / 国务院 | `gov/cn` |
| 求是网 | `qstheory` |
| 国家统计局 | `gov/stats` |
| 国家发展改革委 | `gov/ndrc` |
| 工信部 | `gov/miit` |
| 农业农村部 | `gov/moa`、`agri` |
| 天津 | `gov/tianjin`、`tpre` |
| 人民网 | `people` |
| 新华网 | `news`（新华社）、`mrdx`（新华每日电讯） |
| 半月谈 | `banyuetan` |
| 地方政府 | 85 个（`gov/ah`、`gov/beijing`、`gov/chongqing`…） |
| 研究机构 | 18 个，含 `nifd`（国家金融与发展实验室，正是你库里 NIFD 那批的来源） |
| 行业协会 | 23 个（`caam`、`ccf`、`cast`、`ccfa`、`chinaisa`…） |

**所以"加源"这件事基本是配置工作，不是开发工作。** 这是好消息，也意味着没有必要扩张——因为瓶颈不在源的数量。

## 6. 三个明确的"不做"

### 6.1 不做微信公众号（本阶段）

这是**唯一真正的技术缺口**，而且没有免费可靠解。

RSSHub 的 `wechat` namespace 有 11 个路由文件（`sogou`、`feeddd`、`wechat2rss`、`ershcimi`、`data258`、`uread`、`tgchannel`、`ce`、`mp`、`msgalbum`、`announce`），但**全部依赖第三方服务**，不是自建抓取。微信没有公开 API。

调研还发现：最流行的自建方案 `cooderl/wewe-rss`（9,661★）**已归档**（最后推送 2026-03-20）。

可靠路线都要成本：自建 wechat2rss（需要 Android 代理/MITM）、微信读书 `uread`（需账号，覆盖有限）、或付费聚合服务。

**结论：把微信从自动化目标里摘出去。** 需要哪些公众号，手动转存。不要让一个 5% 的需求阻塞 95% 的进度。

### 6.2 不做自动分类

调研结论很明确：**找不到可用的、免费的、Windows 原生的中文政策分类器。** GitHub 上所有相关仓库都是学术训练框架（要你自己标注数据 + torch），而且严重过期（2,198 天 / 2,922 天 / 824 天）。

而你的实际需求也不大：6 条路由只对应 4 个目标分类，**分类基本由来源决定**。用"每源 → 分类"的映射 + 少量关键词规则就够。细分到子类时，靠你在拆解卡里手填 `主题簇`。

### 6.3 不做 Zotero 自动归类

你自己选的"手动归档"是对的，而且调研给了硬证据：**`zotero/translators` 里没有 `gov.cn` / `qstheory.cn` / `stats.gov.cn` / `mof.gov.cn` 的 translator**。所以点"保存到 Zotero"拿到的是**通用网页条目**，不是带发文机关、发文字号的政策记录——元数据本来就得手动补。

未来若想加速，`pyzotero` 已带本地 API CLI（`createitem --collection --tag`、`createcollection --parent`），**但本地写入需要 Zotero 10+**（7-9 只能读，写要走 Web API key）。到时候再评估。

## 8. 遗留技术债（记录备查）

1. **2 条路由失效**：`/gov/mof/bond`（`liBox` 选择器）、`/gov/zhengce/zuixin`（`h4 a` 选择器）。修法明确。
2. **RSSHub 生产模式**：目前用 `pnpm dev`（tsx watch）。长期应 `pnpm build && pnpm start`（`node dist/index.mjs`）。
3. **PowerShell 执行策略**：本机 shell 是 **Windows PowerShell 5.1**，默认按 GBK 读 `.ps1`。含中文的脚本必须存成 **UTF-8 with BOM**，否则中文被解码坏导致语法错误。运行脚本还需 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`。
4. **`.ps1` 脚本位置**：`test-local-rsshub.ps1` 已加 BOM，可直接复用。
5. **pnpm 缓存**：位于 `D:\.pnpm-store\v10`，占磁盘。
6. **调研报告**：完整版在 `news-pipeline-research.md`（236 行，含各类工具的星数/许可证/活跃度实测、以及"死路"清单）。**注意它的框架是按旧的 5 源方案写的，结论部分需按本方案重新校准。**
